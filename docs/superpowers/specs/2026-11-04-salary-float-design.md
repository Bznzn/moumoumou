# macOS 实时收入悬浮窗设计

日期：2026-11-04。状态：用户已在对话中批准设计，待实施；本文不是原生交互已经实现的证明。

## 意图与成功标准

用户希望在上班时看到今日收入不断增加，获得赚钱的满足感和工作动力。应用使用 Electron，作为安静的小悬浮窗放在 macOS 桌面，不妨碍操作后方窗口。

成功表现：设置月薪与作息后，工作期间自动累计；金额变化精致可感；日常无需打开主界面；重启、休眠、退出后重新打开仍显示按计划作息计算的金额。

## 用户已确定的需求

- 按当月计划工作总时长折算每秒收入，完整走完当月计划工时，收入等于该月月薪。
- 工作时间增长；午休、下班和休息日暂停。
- 每天共用一套上下班与午休时间。
- 支持固定每周工作日，以及大小周两周循环。大小周默认大周周一至周六上班，小周周一至周五上班，周日固定休息。
- 大小周有参考周与大/小周设置，跨月连续循环；支持单独修改某一天为工作或休息。
- 采用「深色精品」外观：石墨黑、细腻金属层次、少量香槟色高光。
- 金额变化时仅变化数位向上滚动，达到整额时出现一次柔和微光。
- 单击穿透至后方窗口；可直接拖动，用户明确希望使用 macOS 三指拖动；不设置额外的解锁按钮。
- 鼠标移到悬浮窗区域时自动半透明，移开恢复。
- 进入其他应用的全屏空间仍显示，但自动半透明，点击穿透仍保留。
- 下班后保留今日金额，停止增长，显示「今日收工」。
- 登录 Mac 后自动启动并显示；不弹设置窗口。
- 加入收入概览：本月累计、每日收入、计算明细。
- 调薪可选本月或下月生效，默认下月。本月生效会重算本月今日金额及历史，更早月份不变。

## 方案比较与建议

用户已指定 Electron，以下实现细节由设计者建议，并随整份设计一起获得批准。

1. **纯 Electron**：主进程管理菜单栏和窗口，渲染层绘制 UI。透明度、跨全屏显示、鼠标穿透具有官方 API；但无法据此证明「单击跨应用穿透，同时三指拖动同一悬浮窗」可行。
2. **Electron 为主，必要时加入小型 macOS 原生辅助模块（建议）**：保留 Web UI，针对手势、跨空间状态及窗口路由使用经过验证的公开系统接口。代价是额外的构建与平台维护。
3. **完整原生应用**：更贴近系统窗口行为，但不符合用户指定 Electron 的方向，本轮不采用。

选择以 Electron 为主，先做原生交互可行性验证，根据证据决定是否需要辅助模块。不得把“增加原生模块”当成可行性的保证。

### 实现前必须通过的可行性验证

当前对话中的效果都是网页概念预览。部分预览在同一页面内区分单击与拖动，并模拟对后方元素的点击，这不能证明跨应用事件路由成立。

首先建立最小 macOS 原型，验证：

1. 悬浮于普通应用及其他应用的原生全屏 Space 上，能够识别并应用对应透明度。
2. 单击悬浮窗覆盖范围时，后方真实应用正常收到单击；按下、抬起与焦点行为不出现重复或意外操作。
3. 用户在系统启用三指拖动后，可从悬浮窗覆盖范围直接移动悬浮窗，无需先解锁；不会拖动后方应用。
4. 穿透时仍可检测光标进出并调整透明度。
5. 拖动结束、休眠唤醒、全屏切换、多显示器切换后，恢复正确状态。

仅使用公开、可维护的接口。若任何关键组合无法可靠完成，应记录复现情况、系统版本和可行替代方案，回到用户确认交互取舍；不得静默增加解锁按钮或把模拟事件冒充系统能力。最终版本的该能力在此验证前不作保证。

参考：[Electron 窗口交互](https://github.com/electron/electron/blob/main/docs/tutorial/custom-window-interactions.md)、[BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)、[Apple 三指拖动](https://support.apple.com/en-ng/102341)。

## 界面与交互

### 悬浮窗

设计者建议默认约 300 × 182 个逻辑像素，首版固定尺寸，可拖动并保存位置。

```text
今日已赚                         · 赚钱中

¥ 238.64

──────────────────────────────────
+ ¥0.0181 / 秒                  18:00 下班
```

- 今日金额保留两位小数，每秒收入显示四位；内部不以这些显示舍入值累计。
- 使用系统字体和等宽数字，避免金额变化引起布局抖动。
- 外观采用已经选择的深色精品方案，不再额外增加浅色主题。
- 滚动只影响变化的数位，不整体跳动、不循环闪烁；响应系统减少动态效果设置。
- 设计者建议整额微光默认每 ¥100 触发，可在设置选择每 ¥10 / ¥100 / 关闭。阈值本身还未由用户指定。
- 仅在前台实时增长跨过阈值时触发一次，重开应用、重算、恢复显示不补放历史奖励。不加声音。

### 透明度状态

以下数值来自效果预览，作为首版设计默认值，设置可调整：

| 状态 | 不透明度 |
| --- | --- |
| 普通工作且未悬停 | 100% |
| 普通工作且悬停 | 28% |
| 全屏且未悬停 | 45% |
| 全屏且悬停 | 20% |
| 正在移动悬浮窗 | 100%，便于定位 |

过渡约 180–220 毫秒。拖动优先于悬停和全屏淡化；松手后恢复相应状态。透明度与事件路由分离，变淡不能自行变成拦截单击。实现仍受上述原型验证约束。

### 作息状态

- 上班前：今日 ¥0.00，显示今日开始时间。
- 工作中：自动累计，显示「赚钱中」及下班时间。
- 午休：金额暂停，显示「午休中」及恢复工作的时间。
- 下班后：今日金额保留，显示「今日收工」，停止实时增长。
- 休息日：今日 ¥0.00，显示「今日休息」及下次计划上班时间。

上班前、午休和休息日的具体文案是设计者默认选择，用户已确定暂停规则，但未单独选定这些文案。下班后不保证“明天”一定上班，应从排班中查找下次工作日期。

### 菜单栏及辅助窗口

菜单栏是主要入口，避免与悬浮窗单击穿透冲突。提供显示/隐藏悬浮窗、收入概览、设置、退出。

设置与概览是普通可交互窗口，不穿透，不套用悬浮窗的悬停淡化规则。首版建议常驻菜单栏，不常驻 Dock；正常打开设置窗口并允许键盘操作，不抢后方应用焦点。

首次打开且无有效配置时才展示设置；后续登录只显示菜单栏和悬浮窗。登录启动设置可关闭；退出明确终止程序，隐藏悬浮窗不终止程序。

### 首次设置与排班

沿用已展示的一屏设置方向，输入月薪、排班方式、作息，并实时预览每秒收入。

- 默认人民币；月薪由用户填入，用户自行选择填税前或实发数额，应用不计算税费。
- 固定排班：自由选择每周上班的星期。
- 大小周：设置参考周所在日期及该周类型。以周一为周起点计算两周循环，跨年跨月不重置。
- 排班日历展示工作与休息日期；点击日期建立手动覆盖，再次切回基准排班可清除覆盖。
- 手动日期覆盖优先于循环排班，适用于补班、调休和特殊休息。
- 默认作息建议 09:00–18:00，午休 12:00–13:00；均可修改，可关闭午休。示例值不是用户实际作息。
- 首版限当天上下班，不支持跨午夜班次；校验上下班顺序、午休范围、正数月薪及有效计划工时。
- 首次设置读取并保存系统 IANA 时区为工作时区，避免旅行或系统时区变化默默改写历史；这是设计者选择。首版不提供多时区排班。

## 计算规则

金额是按计划作息的收入估算，不是工时打卡、工资核算或支付流水。应用是否运行不改变估算。

令月份 m 的月薪为 S(m)，该月每个工作日的计划有效时间区间为 I(d)，有效区间排除午休：

- 当月计划总秒数 T(m) = Σ duration(I(d))。
- 每秒收入 R(m) = S(m) / T(m)。
- 今日截至时刻 t 已赚 E(d,t) = R(m) × Σ duration(I(d) 与当日开始至 t 的交集)。
- 本月截至 t 已赚：累加当月各天的对应有效秒数，再乘 R(m)。

对日金额显示分别舍入到分；月总额直接从未舍入的有效总时长计算，不累加显示值，避免累计误差。

时间计算应基于墙上时钟和计划区间，不能靠定时器每次加一小笔钱。定时器只负责更新显示。重启、唤醒、系统时间变化后重新计算；金额不得超过该日计划金额，完整月累计应等于月薪（在显示舍入范围内）。

首次设置后提供当前月从月初起的计划收入；不是从安装当天开始累计。此前无月薪记录的月份不编造历史。历史日期的工作时长也由保存的计划推导，不声称记录了实际工作时长。

某月没有有效计划工时则显示不可计算状态，收入为零，不除以零，并提示调整排班。找不到下一上班日时显示「暂无工作安排」。

### 修改配置与历史

- 月薪按生效月份记录；本月修改重新计算整个本月，下月修改不改本月，更早月份不变。
- 调整常规作息或排班规则时也选择本月或下月生效，默认下月；规则保存版本，避免当前设置追溯改变更早月份。这是与调薪保持一致的设计者选择。
- 修改日历中特定日期时，仅影响该日期所在月份；由于该月总工时变化，会重新折算整个月的每秒收入和各日金额。设置保存前清楚展示此影响。
- 工作日与休息日覆盖不改变大小周参考周，不使后续轮换错位。

## 收入概览

从菜单栏打开普通窗口，显示：

- 当前月份、该月累计收入、该月月薪与进度。
- 每日金额列表；今天的记录随时间更新，休息日明确标注。
- 日期明细：当日作息、午休、有效时长、该月每秒收入。
- 可切换已配置过的月份；未来月份只展示计划，不标成已经赚到。
- 四舍五入后的逐日显示之和可能与月总额差一两分；总额始终以未舍入结果为准。

不增加排行榜、复杂图表、目标系统或云同步。

## 实现结构与本地数据

以下为设计者建议：TypeScript，Electron 主进程与受限 preload，React 渲染层，Vite 构建。不在设计阶段固定依赖版本，实施时检查兼容性并锁定。

- 计算模块：纯函数处理月份、时区、区间、工资版本、循环排班和日期覆盖。
- 主进程：本地存储、登录启动、菜单栏、窗口位置、显示器与窗口透明度；必要时接入原生模块。
- preload：仅暴露校验过的配置、查询与窗口操作，不把完整 Node 或任意 IPC 暴露给渲染层。
- UI：悬浮窗、首次设置、排班日历、设置、收入概览。
- 本地保存到系统应用数据目录，包含 schema 版本、月薪版本、排班版本、日期覆盖、外观设置、窗口位置、登录启动偏好。
- 原子写入并保留最近一次有效配置；配置损坏时可恢复，不静默清空。收入可从计划重算，避免逐秒落盘。
- 不要求账户、联网服务或云端数据库；本机文件不是默认加密保险箱，不宣称操作系统之外的额外加密保护。
- 多显示器默认只保留一个悬浮窗；记录显示器和相对位置，显示器移除时夹回可见工作区域，避免丢失窗口。
