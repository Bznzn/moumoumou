# macOS 原生交互诊断原型

这不是正式收入应用。用途是验证用户要求的「单击穿透到其他应用 + 系统三指拖动悬浮窗 + 悬停淡化」。网页中的相同行为不能证明原生系统可行。

## 运行

在本目录运行 `npm run build:native`，然后 `npm start`。Electron 45.2.2 的原生安装包最低系统要求已确认为 macOS 13.0；本机为 arm64 macOS 13.7.8。

如果刚安装依赖且 Electron 二进制缺失，执行 `node node_modules/electron/install.js`。Electron 45 的 npm 包没有自动 postinstall 钩子。

控制台中的「打开独立原生后方窗口」启动单独进程的 AppKit 窗口，记录实际收到的 down、up、drag，不是网页模拟点击。

三种模式是实验对照，不是正式产品中的解锁入口：

1. 纯穿透：点击、拖动都送到后方应用，悬浮窗本身不能移动。
2. 正常拖动：Electron 原生拖动区接收拖动，但不穿透单击。
3. 实验组合：在权限允许时，原生事件适配器区分单击和拖动。未获权限即退出并保持纯穿透，不能报告为组合已成功。

## 实验组合所需权限

原型不会自动申请、授予或修改权限。需要用户自行决定是否授予这个本地辅助程序**辅助功能**权限：

`build/SalaryGestureProbe.app`

从仓库根目录打开 `prototypes/window-interactions/build/SalaryGestureProbe.app`。

在「系统设置 → 隐私与安全性 → 辅助功能」点击添加，使用文件选择器的「前往文件夹」定位以上路径并启用。授权后回到原型，再点击「实验：单击穿透＋直接拖动」。控制台必须显示“已连接”后再测试。

这项系统权限允许程序观察/控制鼠标输入。实现不监听键盘内容、不联网；适配器只改变在悬浮窗覆盖范围内开始的鼠标事件：单击延迟到释放后重放，拖动则不交给后方窗口。它仍可能存在系统事件时序兼容问题，必须实际验证；不应拿任意重要操作作为首次测试目标。

若辅助功能已开启而事件 tap 仍不可用，应先检查日志并报告原因，不自动要求更多权限；输入监控是否需要另行授权以具体系统反馈为准。

结束实验从菜单栏「薪·测试 → 退出原型」退出。可在系统设置关闭并移除辅助程序授权；退出时清理辅助进程，不常驻后台。

## 验证方法

- 单击悬浮窗覆盖范围：独立后方窗口 down/up 各增加一次。
- 系统三指拖动悬浮窗：悬浮窗移动，后方窗口 down/up/drag 不应增加。
- 普通鼠标拖动对照、双击、轻微抖动、拖出范围、切换屏幕及全屏分别记录。
- 45%按钮只验证透明度；不代表已经实现自动识别其他应用全屏。
- 当前原型尚未完成休眠恢复、全屏自动识别和实际三指拖动验收，不能直接作为正式 PlatformAdapter。

运行 `npm test` 验证真实 Swift 路由状态机；15项断言不替代上述系统输入验证。`npm run check` 只检查 JavaScript 语法。日志位于 `evidence/`，不记录键盘文本，未上传。
